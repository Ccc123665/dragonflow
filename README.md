# DragonFlow 一条龙

> AI 全媒体内容智能分发平台 · 自用桌面工具

一个选题 → AI 生成各平台差异化内容 → 人工编辑定稿 → 一键填充到各平台发布页 → 人工确认后一键发布。

支持平台：**小红书 / 抖音 / 视频号 / 公众号 / 头条号**

---

## 一、它做什么，不做什么

**做：**
- **内容工坊（能力驱动）**：**下拉选能力**（可多选，选中的以胶囊列出）→ 点「填写输入」
  在弹窗里一次填完 → 生成。多个能力**共用的输入只填一次**。
  只列**真能干活的**能力：你导入的 Skill 包 + 抓取 / 出图 / 渲染的流水线
- **内容流水线**：公众号文章链接 → 小红书 3:4 干货图文（8 张 1080×1440，本地出图）
- **内容流水线**：文案 → 9:16 竖屏短视频（本地逐帧渲染 + ffmpeg 编码，可加 AI 口播）
- **组合流水线**：公众号文章链接 → **同时**出小红书图文 + 竖屏短视频（一条链接两种产出）
- 每个平台账号独立浏览器 Profile，人工登录一次长期保持
- 一键把内容填充到各平台发布页（标题、正文、话题自动写入）
- **发布前体检**：字段长度 / 必填 / 站外引流 / 排版 + 广告法词库，填充前先查一遍
- **目标账号 + 差异化分配**：选发到哪些账号；同平台多账号可一键生成差异化版本
- 合规检测（广告法极限词 / 教育行业敏感词 / 平台规则词）
- 素材库归档、发布记录台账、**本地数据看板**（只用本机数据，不联网）

**不做：**
- ❌ 定时发布 / 无人值守批量分发
- ❌ 平台开放 API 发布（个人身份拿不到资质）
- ❌ 数据自动回流（不做爬取）
- ❌ 保存任何账号密码
- ❌ 云端生成 / 云端存储（出图、渲染、口播全在本机完成；口播需联网调用 edge-tts 的语音接口）

### 它不是 Agent —— 这条边界要认清

本工具是「**固定流程的执行器**」，不是「会自己想办法的 Agent」。区别很实在：

| | Agent（Claude / WorkBuddy） | 本工具 |
|---|---|---|
| 遇到没见过的页面 | 自己换招、重试、写新代码 | 按写死的分支报错 |
| 读图片里的数据表格 | 能（视觉） | 能（接 `deepseek-flash` 这类多模态模型，勾上「读原文配图」就读） |
| 步骤由谁定 | 模型临场决定 | 代码写死 |
| 成本 | 每次都在烧 token | 除生成文案外几乎零成本 |
| 稳定性 | 同一输入可能给不同做法 | 同输入同输出，可复现 |

**推论**：把一份 `SKILL.md` 丢进本工具，得到的是「一段可以塞进提示词的方法论」，
**不是**「一个会干活的员工」。真要让它干活，得把 skill 里的动作**翻译成 `src/pipelines/`
下的代码** —— 这就是 `gzh_to_xhs` / `xhs_video` 做的事。

**两条路，路 1 是主线：**

| | 路 1：装了 Skill，输入指定内容 → 输出指定内容 | 路 2：只给选题和要求，让大模型思考 |
|---|---|---|
| 长什么样 | 「公众号链接转小红书图文」—— 贴链接，出文案 + 8 张图 | 选「小红书图文」→ 填选题 → 生成 |
| 靠什么干活 | **pipeline**：`src/pipelines/` 下的代码，真的会抓取 / 出图 / 编码 | **prompt 模板**：一次模型调用，只产出文字 |
| 需要你上传吗 | 要（或者直接用内置的流水线） | **不用**，五个平台都内置了通用模板 |
| 能干的活 | 抓网页、渲染图片、编码视频、读写本地文件 | 写文案、写口播脚本、写分镜提示 |
| 干不了的活 | —— | 抓取 / 出图 / 出视频（这些必须写成 pipeline） |

> **主线是路 1。** 路 2 只产出文字，要图片、要视频都做不到 ——
> 所以它现在只作为「没有对应 skill 时的兜底」，不再是重点。
> 你后续要做的能力（链接 → 多选图文/视频/长图文、选题 → 指定内容）
> 都按 skill 形态上传，走的就是路 1。

> ⚠️ **v1.3 起，内容工坊只列「真能干活的」形态：`bundle`（Skill 包）+ `pipeline`（流水线）。**
> 上表里的「路 2」（6 个 `prompt` 基础模板）**不再出现在工坊**里 ——
> 它们仍然在「设置 → 内容模板 Skill」里可查看 / 停用 / 恢复，只是不占工坊的位置。
> 3 条内置流水线**留在工坊**（用户明确说「这三个就算是我上传的 skill」）。
> 想让 `prompt` 也回到工坊，改 `skills.STUDIO_KINDS` 这一个元组即可
> （`("bundle", "pipeline")` → 加上 `"prompt"`）。

**关键**：路 1 的能力**输入输出是固定的**，界面直接把它写清楚。
一个能力 = 一个 `pipeline`（代码）+ 一条模板条目（`kind: pipeline`）。
「链接 → 图文」「链接 → 视频」是两个能力，勾两个就**一条链接同时出两样**。

路 2 的边界要说清：**它只产出文字**。要图片、要视频，必须走 pipeline 形态（路 1）。
你上传的 Skill 如果在描述里写了「抓取 / 出图 / 渲染」，但形态只是 `prompt`，
本工具会在导入时和设置页「自检」里明确警告 —— 它不会真的去抓、去画。
（见「四·五 → 可用性自检」）

**怎么分工**：
- **固定、可复现、要重复跑**（抓取→出图、文案→视频、批量填充）→ 写成 pipeline，比 Agent 更快更稳更省
- **需要看图、需要临场判断、一次性探索** → 留在 Agent 侧做，别硬塞进来

**登录与发布全部由人工触发。** 公众号只填充内容并保存草稿，不自动群发。

## 二、运行

### 开发态

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python src\main.py
```

或直接双击 `启动.bat`。

> 内容流水线（公众号转图文 / 文案转短视频）还需要
> `Pillow` `requests` `edge-tts` `imageio-ffmpeg`，都写在 `requirements.txt` 里。
> 只跑前四个视图不装也能用，只是点流水线模板会报缺依赖。

### 首次使用

1. 打开「设置」→ 选服务商 → 填 API Key → 点「测试连接」
2. 进「发布工作台」→ 左上角 `☰` 展开「账号矩阵」→ 点 `+` 添加账号（每个平台可加多个）
3. 点账号行（或点平台名）→ 在弹出的浏览器里扫码登录
4. 回到「内容工坊」→ **在下拉里选要跑的能力**（可多选）→ 点「填写输入」在弹窗里填完 → 点「开始生成」
   - 选几个能力，它们的输入会**合并成一张表单**，共用的输入只填一次
     （选「链接转图文」+「链接转视频」→ 弹窗里只有一个「公众号链接」输入框）
   - 跑不起来的能力**也会列在下拉里**（标「（不可用）」+ 点不动），
     不会藏起来让你以为没上传成功；鼠标悬停能看到原因
   - 上传新能力在「设置 → 内容模板 Skill」（支持选文件 / 选文件夹 / 导入压缩包）
5. 点「去发布 →」进入「发布工作台」→ 点「打开发布页」→ 点「一键填充」
   （填充前会自动跑一遍发布前体检，有必改项会拦一下）
6. 逐个平台页面核对内容 → 点「一键发布」
7. 想看产出统计，点顶部「数据看板」

#### 模型怎么填（踩过坑，写清楚）

「模型」要填**接口里的模型 ID**，不是官网控制台上显示的**名字**。两者经常不一样：

| 官网显示名 | 接口认的 ID |
|---|---|
| DeepSeek-V4.1-Flash | `deepseek-flash` |
| DeepSeek-V4.1-Pro | `deepseek-v4-pro` |

填错会报 `400 invalid_request_error`。不想记也没关系，两个入口帮你兜：

- **「拉取可用模型」按钮** —— 直接问服务端"这个 Key 能用哪些模型"，拉回来填进下拉框，
  当前填的 ID 不在列表里会自动切到第一个可用的
- **报错自动纠正** —— 服务端说「supported API model names are X, Y」时，
  界面会把这句里的模型名抠出来、直接填好下拉框，并提示你点一下「测试连接」

**推理模型的额度坑**：`deepseek-flash` / `deepseek-v4-pro` 都是推理模型，
**思考过程也占用输出 token**。实测 `max_tokens=1200` 时三次调用里有一次思考把额度全吃掉、
正文返回 0 字，另外两次 JSON 被截断。所以：

- 推理模型的输出额度会自动抬到下限 **6000**（设置里填小于它的值也会被抬）
- 被截断（`finish_reason == "length"`）时**自动翻倍重试一次**，取更长的那份
- 设置页会实时显示「实际按 N 发出」，并提示写长正文时调到 8000 以上

## 二·五、界面结构（v1.0 改版后）

```
┌────────────────────────────────────────────────────────────────┐
│ [D] DragonFlow 一条龙 │ 内容工坊 发布工作台 素材库 发布记录 数据看板  设置  ─ □ × │  ← 全部在标题栏
├────────────┬───────────────────────────────────────────────────┤
│            │                                                   │
│  账号矩阵   │                                                   │
│          ⟨⟨│  ← 蓝色渐变手柄，骑在分界线**竖向中点**上             │
│            │                                                   │
│            │                  当前页面内容                       │
├────────────┴───────────────────────────────────────────────────┤
│ 执行结果  小红书·公考干货号A 已填充  …                           │
└────────────────────────────────────────────────────────────────┘
```

- **导航和设置都在标题栏里**，没有独立的导航行 —— 竖向空间全留给内容。
  窗口变窄（< 1240px）时副标题自动隐藏，避免把导航挤变形。
- **窗口**：无边框自绘，四边 + 四角都能拖拽改大小；标题栏空白处可拖动移动窗口，
  双击最大化；最大化状态下拖动会自动还原。
- **初始尺寸按屏幕「可用区」算，不是硬写死的**（`MainWindow._fit_to_screen`）。
  期望值 1440×940 只是「想开多大」，真正落地时会跟
  `screen().availableGeometry()`（**已扣掉任务栏**）取交集，再居中摆好。
  1366×768 的笔记本上可用区只有 1366×728，硬开 1440×940 会让窗口底边
  **整条藏到任务栏下面**，最下面那排控件全都点不到 —— 这是实报的问题。
  最小尺寸也跟着一起压，否则 `setMinimumSize` 会把窗口重新顶出屏幕。
- **账号矩阵只在「发布工作台」出现**。内容工坊 / 素材库 / 发布记录下不显示。
- **收起侧栏有两个入口，都看得见、点得到**：
  1. 侧栏标题行右侧的 **« 收起按钮**（`chevron_left`）—— 这是主入口。
  2. 骑在分界线上的 **蓝色渐变手柄**：20×50，常态透明度 0.85（不是以前的 0.55），
     箭头 14px / 描边 2.6px。收起后落到窗口最左边，点它展开。
  侧栏右缘还有一条 3px 的**渐变指示线**（上淡 → 中浓 → 下淡），提示「这里可以收」。
- **手柄竖向居中**（`y = (body.height() - hh) // 2`）。以前是贴底的
  （`body.height() - hh - inset`），两个毛病：视觉上像掉在角落里的一颗扣子；
  而且底部一有东西（工作台的「执行结果」条）就得往上让，让多少还得靠
  `workbench.bottom_bar_height()` 去估 —— 布局一改就压住它。
  居中之后这两件事一起消失（那个 `bottom_bar_height()` / `_notify_handle()`
  已经删掉了）。手柄 20px 宽、骑在分界线上，只有 10px 探进侧栏，
  正好落在侧栏 12px 的右边距里，压不到账号行右侧的「+」。
- **收起后会给手柄留一条 30px 的左侧空隙（gutter）**。原因：手柄是浮层，
  侧栏宽度归 0 之后它只能压在内容区上，而内容区里是 `QWebEngineView`（原生窗口），
  浮层压在上面**既可能被盖住、点击也可能被吞掉** —— 用户就再也展不开侧栏了。
  在 `body` 布局左侧留出空隙，手柄完全落在空隙里，从根上避开这个坑
  （`main.MainWindow._apply_gutter`）。展开时空隙自动收回。
- **手柄的位置必须挂到 `body` 的 `Resize` 事件上，不能挂在窗口 `resizeEvent` 里**。
  Qt 的布局是事件循环稍后才激活的，窗口 `resizeEvent` 里读 `self.body.height()`
  拿到的是**旧值**，窗口一变小手柄就被算到屏幕外 —— 这正是「收不起来」的真凶
  （`MainWindow.eventFilter`）。
- **弹窗化**：待发布内容、目标账号、批量导入选题、账号编辑、模板编辑、新增平台
  全部走自绘弹窗（自绘标题栏 + 圆角 + 投影 + 可拖动 + 按内容自适应高度，超屏自动滚动）。
- **浏览器标签页带关闭 ×**：关掉当前标签会自动切到相邻的；全关完回到空态。
- **所有「选择」都用打勾，不用蓝白色块**。勾选框选中 = 主色底 + **白色对勾**
  （对勾是 `theme.check_tick_path()` 现画的 PNG —— QSS 的 `indicator:checked`
  光写 background 只会得到一块纯色方块，没有对勾）。矩阵分配的账号勾选、
  目标账号勾选、发布前确认开关，全部统一成这套。
  （工坊 v1.4 起把「选能力」改成了下拉 + 胶囊，不再用一屏勾选框 —— 见「二·六」。）
- **下拉框必须看得见箭头**：QSS 里 `QComboBox` 不给 `down-arrow` 的话，
  它长得和输入框一模一样，用户看不出「这里能点开选」。箭头由
  `theme.icon_png()` 把矢量图标渲染成 PNG 再拼进样式表（**QSS 的 `image:`
  只认文件，不认 QIcon**）。
- **鼠标悬停即可点的地方一律是手型光标**（Qt QSS 不支持 `cursor`，
  用全局事件过滤器实现，见 `theme.install_cursor_filter`）。
- **发布工作台工具栏**：待发布内容（弹窗）· 目标账号 · 发布前二次确认 ·
  打开发布页 · 一键填充 · 一键发布。点填充 / 发布前会先跑一遍体检，
  有必改项时弹框拦一下（可以选「仍然继续」）。
  - 「矩阵分配」不再单独占一个按钮 —— 它本质也是「发到哪些账号」，
    已收进「目标账号」弹窗里的「差异化分配…」入口，工具栏少一个重复项。
  - 「发布前二次确认」开关只控制**一键发布**要不要先弹确认框，**不影响一键填充**（悬停有说明）。
- **账号矩阵侧栏**：平台下显示账号名；**没登录过的账号不会被写成「正常」** ——
  显示灰点和「未登录」标签，也不会被默认勾选进发布目标。点这一行打开发布页扫码，
  登录后程序会自动探测并标记（不再「打开过发布页就算已登录」）。
- **账号改名入口不用翻右键菜单**：鼠标移到账号行上，行尾会浮出 **铅笔按钮**
  （`edit`），点开就是「编辑账号」弹窗，可改名字、人设、分组。右键菜单里也有同一项。
  之前改名只有右键一条路，用户找不到，所以补了这个显式入口
  （`sidebar.AccountRow.btn_edit` → `edit_requested` → `Sidebar._edit`）。
- **应用图标**：程序化的蓝紫渐变圆角方块 + 「分发」符号（一源连三目标），
  已同时设进窗口图标、Windows 任务栏（AppUserModelID）和打包 EXE。
- **数据看板**：近 14 天完成量柱状图、平台分布、状态构成、账号产出排行。
  数据源只有本机的 `records.json` 和 `library.json`，不联网、不上报。

## 二·六、内容工坊：下拉选能力 → 弹窗填输入 → 生成（v1.4）

页面只有三块：**hero + 一块「选能力与输入」卡 + 一条生成动作条**，下面是结果区。

### 能力从哪来：**只列 Skill 包 + 流水线**

工坊里只出现两种形态：

| 形态 | 是什么 | 在工坊里 |
|---|---|---|
| `bundle` | 从「设置 → 内容模板 Skill」整包导入、带 `SKILL.md` 的那种 | ✅ 列 |
| `pipeline` | 抓网页 / 出图 / 渲染视频的多步流程（`src/pipelines/` 下的代码） | ✅ 列（3 条内置的都留着） |
| `prompt` | 一次模型调用、只产文字的基础模板（内置 6 个） | ❌ 不列 |

口径来自用户原话：**「只要 skill，不要其他内置」** + **「这三个（流水线）就算是我上传的 skill」**。
所以判据不是「是不是内置」，而是**「能不能真的干活」** —— 只产文字的基础模板不占位置。

不列不等于消失：它们仍然可以在设置里查看 / 停用 / 编辑 / 恢复。

开关只有一处：`skills.STUDIO_KINDS = ("bundle", "pipeline")`。想放开或收紧，
改这一个元组就行 —— 下拉条目、默认选中、空态判断、计数全跟着走。

一条能力都没有时（把内置流水线也全删 / 停用了才会走到），工坊给的是
**引导面板**（图标 + 说明 + 「去上传 Skill 包」/「打开 Skill 目录」两个按钮），
不是一句干巴巴的灰字。

### 视觉：下拉 + 胶囊 + 弹窗（v1.4 精简）

v1.3 把每条能力铺成一张实体卡片（名称 + 描述 + 要填/会得到 + 两个胶囊），
十几条能力就是一屏多的列表。用户的原话是**「选择能力做成下拉选择，不用把所有能力
都详细列出来，填写输入改成弹窗，尽量精简」**，于是：

```
┌─ hero（主色渐变）──────────────────────────────────────────────┐
│ (笔) 内容工坊                   Skill 包 + 流水线 · 共 6 个能力 │
└────────────────────────────────────────────────────────────────┘
┌─ ① 选择能力与输入  可多选，共用的输入只填一次  已选 2 个 [管理/上传] ┐
│  能力  [ ＋ 从下拉里挑一个能力…                        ▾ ]  [＋ 添加] │
```

- **能力下拉**：一行装下「名称 · 形态 · 平台」，**描述 / 要填 / 会得到这些长文本
  挪进 tooltip** —— 信息不丢，页面不铺开。选中即加入清单（不用再点一次确认），
  加完下拉复位成占位提示，方便连着加下一条。
- **已选能力是一排胶囊**：平台色点 + 名称 + `×`。点 `×` 摘掉，
  比回到下拉里取消勾选直观。已选过的项在下拉里带一个勾选图标（**用 item icon，
  不用「✓」字符** —— 字符在字体不全的环境里会渲染成豆腐块）。
- **排序：能跑的在前、流水线优先**。流水线是真会抓取 / 出图 / 渲染的那批，
  排最上面（首次进来默认选的也是第一条）；跑不起来的垫底，
  但**仍然列出来**，只是标「（不可用）」+ 在 model 里 `setEnabled(False)`。
- **输入摘要是一条下沉条**：左边一句「要填 A、B、C 等 N 项 · 还差『X』」，
  缺必填时是灰的、齐了转绿；右边一个主色按钮开弹窗。
  点「开始生成」时若还缺必填，**直接把弹窗顶出来**，而不是只弹个 toast。
- **生成区收成一条动作条**：主色渐变底，左边一句状态（「准备好就开跑」→
  「正在跑：xxx」），右边一个大号主色按钮。

### 两个容易踩的实现点

- **输入的权威来源是缓存，不是控件**。弹窗关掉后控件就销毁了，
  再读控件必然读到空。所以值存在 `self._input_values`，弹窗保存时落进去。
  ⚠️ 缓存里**没有**的 key 要补 `Input.default`：开关 / 下拉这类输入一进来就有默认值
  （「读原文配图」默认开、「出图页数」默认 8），用户没打开过弹窗时缓存是空的 ——
  不补默认值，摘要会一直误报「还差『读原文配图』」。
- **重开弹窗要带回上次填的值**。`make_input_editor(inp, values={...})` 是新增的
  按 key 预填；老的 `topic` / `prefill` 两个参数保留原语义（只灌给特定 key），
  因为 pipeline 弹窗里 `prefill` 是「上游产出的整篇正文」，
  一视同仁的话「补充要求」这种小框也会被塞满。

### 其它没变的行为

- **跑不起来的能力也列出来**（不藏）：下拉里标「不可用」+ 点不动，
  tooltip 里显示第一条 `err` 原因。藏掉用户会以为「没上传成功」。
- **共用输入只出现一次**：`merge_inputs()` 把多个能力的输入按 key 去重。
  选两个 Skill 包，两边都要「选题」，弹窗里就只有一个框，填一次两边都用。
- **结果卡片按能力分**（key 是 `skill_id`），带产物缩略图，
  点「去发布 →」把该能力的产出推给工作台。

上传端口在「设置 → 内容模板 Skill」，导入后立刻自检能不能跑（见「四·五」）。

## 四、平台适配脚本（重要）

各平台发布页的 DOM 结构会变。适配脚本独立在 `src/assets/adapters/*.js`，
**改版时只改 JS 文件，不需要重新打包主程序**——把新 JS 覆盖过去即可。

约定：

```js
window.DragonFlow = {
  name: '小红书',
  ready:    function () { return true | false },      // 页面是否就绪（未登录返回 false）
  fill:     function (payload) { return {ok, filled, missing, message} },
  submit:   function () { return {ok, message} },
  diagnose: function () { return {url, login, title, editor, ...} }   // 可选，供「诊断」按钮
};
```

`_common.js` 会被自动前置注入，提供这些工具：

| 函数 | 用途 |
|---|---|
| `DF.one / DF.many` | 按选择器数组找元素（依次试，命中第一个） |
| `DF.setValue(el, v)` | 写 `<input>`，走原型原生 setter，能触发 React 的 onChange |
| `DF.typeRich(el, v)` | 写 contenteditable，让编辑器当成用户输入 |
| `DF.byText(texts, tag)` | 按可见文本找按钮 |
| `DF.clickEl(el)` | 点击（补一套鼠标事件序列，兼容只监听 mousedown 的页面） |
| `DF.findTab(labels) / DF.clickTab(labels)` | 按文本找「标签页」并点击，取最深命中的元素 |
| `DF.visible(el)` | 可见性判定（`offsetParent` + 非零尺寸） |

**每个平台一个适配器，互不影响。** 某个平台失效不影响其他平台。

**兜底**：适配脚本缺失或注入失败时，流程降级为「复制到剪贴板 + 打开发布页」，人工粘贴，不会卡死。

### 异步页面怎么等：`retry` 协议（重要）

Qt 的 `runJavaScript` **不会 await Promise** —— `Promise.resolve({ok:true})` 回到 Python 侧
只是个 `{}`。所以适配脚本里**不能**写 `await sleep(1200)` 再往下填，页面还没渲染好就是没渲染好。

约定：脚本发现「还没就绪但不是错」时，返回 `retry: true`，由发布队列延迟重跑同一项：

```js
return DF.result(false, [], [], '正在切到「上传图文」页…', { retry: true, stage: 'switch' });
```

发布队列最多重试 8 次、每次间隔 1.5 秒（`publisher.PublishQueue.MAX_RETRY / RETRY_DELAY_MS`），
进度条上会实时显示「正在切到「上传图文」页…（2/8）」。超限才判失败，并说明「已重试 N 次」。

> 这条限制有专门的回归测试守着：`tests/test_js_promise.py`。
> 哪天 Qt 改了行为、开始 await Promise，那个测试会先红，届时可以把 retry 机制简化掉。

### 一键填充：小红书「先传图才有编辑框」（重要）

小红书的图文发布页是**先传图、才渲染标题 / 正文编辑框**的。所以「一键填充」
必须分两步走，这是真实交互，绕不过去：

1. 脚本发现「页面要求先传素材，但编辑框还没出现」→ **主动帮你点开上传**
   - 这次内容里有配图 → 自动传进去，然后重试，等编辑框出现后填文字
   - 这次内容里没配图 → 会弹系统文件框让你自己选图，
     选完再点一次「一键填充」即可（这时编辑框已经在了）
2. 编辑框出现后 → 标题、正文、话题一次性写进去

所以看到「已帮你点开上传，选好图片后再点一次一键填充」**不是失败**，
是「需人工介入」——结果条上显示为**「需人工」**，不是红色的「失败」。

> 实现上把两件事拆开了：`_want_upload`（**平台要求先传素材**，每次尝试都带）
> 和 `_upload_count`（**这次有几个文件**，只在首次尝试带）。
> 以前脚本用「有没有文件可传」决定点不点上传 —— 内容里没配图时一步都不点，
> 于是永远停在「没有找到正文编辑器」。这就是那个 bug 的根因。

### 生成的图片在哪、怎么传上去（v1.5 媒体状态条）

用户最高频的困惑：「点开上传图片，根本不知道内容工坊生成的图片放到哪里去了」。
根因有两个：图片实际存在 `%APPDATA%\DragonFlow\output\…`（**隐藏目录**），
界面上却只有一行小字路径；真弹系统文件框时起始目录还是空的。
v1.5 起三层修复：

1. **看得见**：内容卡上 `image_hint` / `shot_hint` 不再是可编辑文本框，
   改成只读状态条「📁 配图 · 已出图 19 张 · [打开文件夹] [更换配图]」。
   「打开文件夹」一键直达图片所在目录（`platforms.open_in_explorer`）；
   「更换配图」选个文件夹即换，风格描述行保留、目录行自动重写。
2. **选得到**：就算真的弹系统文件框（内容没图要手动选），
   起始目录自动定位到当前内容的配图目录（`browser.set_suggested_dir`，
   打开发布页 / 切标签 / 填充时都会同步）——一打开就在对的文件夹。
3. **不断链**：`artifacts` 只在内存里，重启就丢。填充时能从 `image_hint`
   文本解析出目录就回写 `it.artifacts`（`_dispatch`），
   缺图弹窗选完目录也会通过 `ContentCard.attach_media` 回写卡片状态条 ——
   发布链路（`upload_files`）拿到的永远是同一份文件列表。

> 顺带修了一个一直没发现的 bug：视频流水线把路径写成「视频文件：…」，
> 而目录解析只认「目录：」—— 视频自动上传的解析其实**从来没通过**。
> 现在 `_path_of` 两种标记都认。

配套测试：`tests/test_media_bar.py`（路径解析 / 建议目录 / 状态条 /
更换回写 / `content()` 语义不变，28 条）。

### 应用内选图器 + 自动挂图（v1.6，A+B+C）

v1.5 之后真机又暴露两个问题：内容来自素材库复用时（artifacts=0、hint 为空），
一键填充还是只能手动选图；页面加载慢时登录探测拿不到答案，
明明登录着却一直挂灰色「未登录」。v1.6 三层修复：

1. **A · 自动挂最新批次**（`workbench._ask_missing_media`）：填充时发现缺图，
   不再直接弹系统框 —— 先找最近产出的批次（`latest_media_dir`），
   有图就问一句「**自动挂上 N 张（来自 X）/ 我自己选**」。
   挂上后自动回写 artifacts + 卡片状态条 + image_hint（`_attach_images`），
   填充时整批自动上传，全程零手动。
2. **B · 应用内选图器**（`widgets/media_picker.py`）：「我自己选」不再弹
   Windows 文件框，改弹自家对话框 —— 左侧是 output/ 下**最近产出的批次列表**
   （按时间倒序，标着时间和张数），右侧缩略图网格（点一下可剔除个别图），
   「用这批」直接交回文件。用户从头到尾不用知道图片藏在 %APPDATA% 深处。
   `browser.chooseFiles` 无预置文件时也走它（开不起来或异常才退回系统框）。
3. **C · 登录探测重试**（`workbench._probe_login`）：打开发布页 4.2s 后探测，
   没拿到答案（页面没就绪）→ +4s **再探一轮**（attempt 计数，最多两轮），
   两轮都拿不到才维持「未登录」。修掉「明明登录着却标未登录」的误报。

> 测试踩坑记录：`QApplication([])`（空 argv）后面一创建 `QWebEngineProfile`
> 就原生崩溃（exit 127、无 traceback）—— chromium 要从 argv 里读自己的参数，
> 测试里必须 `QApplication(sys.argv)`（生产 `main.py` 本来就是这么写的）。

配套测试：`tests/test_media_bar.py` 扩到 60 条（批次扫描 / 对话框交互 /
`pick_media_files` 三态 / `chooseFiles` 五分支 / `_images_in` / 探测重试源码约束）。

### v1.6·1 追加：选完图不用再点「一键填充」

真机反馈：选图器出来了，但整条链路还差两口气 ——

1. **视频批次顶掉图片批次**：`latest_media_dir` 拿「最新含媒体目录」，
   xhs_video 的视频批次比图片批次晚出 3 分钟，「自动挂图」就永远落空。
   → 新增 `platforms.latest_image_dir()`（跳过纯视频批次），
   自动挂图与建议目录都改用它；选图器加 `images_only` 只列含图批次。
2. **填充中途选完图要再点一次**：内容没图 → 适配脚本点开上传控件 →
   选图器这时才弹出 → 用户「用这批」→ 文件开始上传，
   但这一轮填充已按「需人工」收场，用户得再点一次「一键填充」。
   → `browser.set_files_picked_hook`：选图器交回文件时回调界面层，
   回写内容（`_attach_images`）→ 轮询 diagnose 等编辑器渲染出来
   （2s×45 次，期间队列没跑完会先让路）→ **自动补一次填充**。
   不会重复传图：xhs.js 的 `uploadTried` 状态位保证同一页面只点一次上传。

配套测试：`tests/test_media_bar.py` 扩到 **73 条**（视频批次遮蔽 /
images_only 过滤 / hook 触发与复位 / 续跑的队列礼让与超时上限）。

### v1.6·2 追加：18 张上限 + 60s 上传预算 + 超时自动续跑

真机反馈：某条内容挂了 26 张图，填充后页面停在**空上传态**、结果条直接「失败」。
原因：小红书单篇最多 18 张（`platforms.json rules.images.max`），
26 张整批塞给页面的 `input[type=file]` 会被**整批拒收**，一张都传不上。三层修复：

1. **喂给页面前就截断**：`platforms.max_images()` 读平台上限、
   `_cap_images()` 保留前 N 张（视频不受影响）。
   两个入口都堵上 —— 预置路径（`upload_files` 尾部）和
   中途选图路径（`browser._cap_for_platform`）。
   被截断时工作台会 toast 提醒「单篇最多 N 张，已自动取前 N 张」。
2. **上传重试预算放宽**：`PublishQueue.MAX_RETRY_UPLOAD = 40`（约 60s）——
   要传文件的项（`upload_count > 0`）不再用 12s 的普通预算，
   几十张图传完之前不该被判死。超时文案也区分开了。
3. **超时自动续跑**：预置路径的填充在 upload/wait/switch 阶段超时失败时，
   `_on_item_done` 自动排 `_wait_editor_and_refill`（与中途选图的 hook
   同一条续跑链）；`_refill_pending` 去重保证同一账号只排一个。

配套测试：`tests/test_media_bar.py` 扩到 **86 条**（26→18 截断 /
视频不截 / 未知平台 fail-open / 中途选图路径同样截 / 预算与续跑源码约束）。

### v1.6·3 追加：批次按「内容主题」匹配，别题批次不能串挂

真机反馈（用户原话）：「这条素材只有 8 张图，26 张图是因为之前的其他批次，
混在一起了」。根因：output/ 下同时躺着**多个选题**的批次，而自动挂图 /
选图器只按「最新」挑 —— 上一题 26 张的批次比本题 8 张的批次晚几分钟生成，
就把别题的图挂到了本题上。

关键事实：批次目录名 = `_safe(标题)`（`config.output_path(key, _safe(tag))`，
非字母数字汉字换成 `_`、截 40 字）—— **目录名本身就带着题目**，按名字对上即可：

1. **匹配器**（`platforms`）：`_topic_keywords` 把标题 / 目录名按非字词字符
   切成 ≥2 字片段；`batch_match_score` 双向计分（主题片段出现在目录名 ×2，
   目录名片段出现在主题里 ×1 —— 兜住标题被截短的情况）。
   `TOPIC_MATCH_MIN = 2`：至少一个片段命中才算同题。
2. **挑批次**：`latest_image_dir / latest_media_dir` 增加 `topic=""` 参数 ——
   同题批次优先（同分内取最新），全部对不上才退回「最新」（原行为不变）。
3. **选图器**：`list_batches(..., topic=)` 把同题批次排最前并标
   「（匹配本题）」；`pick_media_files(..., topic=)` 带主题时**始终全量扫描**
   （建议目录也可能定位错，得让用户能换回本题批次）。
4. **主题穿透**：`browser.set_suggested_topic(aid, topic)` 按账号记住当前
   内容主题；`_sync_suggested_dir` / `_dispatch` / `_ask_missing_media`
   三处入口全部带上，`chooseFiles` 弹选图器时传给排序。

配套测试：`tests/test_media_bar.py` 扩到 **108 条**（同题/别题/无关主题匹配、
截短反向匹配、选图器排序与标记、chooseFiles 传参、工作台三入口源码约束）。

回归附带修复：`skills._import_pack` 的包形态默认值 —— 注释一直写「没声明
就维持 bundle」，实现却经 `_norm_kind(None)` 收敛成 `prompt`，而内容工坊
只列 `bundle/pipeline`（`STUDIO_KINDS`）→ 用户整包导入的 Skill 进不了工坊。
改为显式默认 `_norm_kind(meta.get("kind") or "bundle", ...)`（声明过
kind/pipeline 的包不受影响）。test_ui_smoke「应识别为 Skill 包」随之稳定。

### v1.6·4 追加：登录状态自动标记 + 目标账号弹窗能看到勾选账号

真机反馈：「在抖音登录了之后，依旧显示未登录，并且在目标账号列表里面
选不到它」。两个根因叠加：

1. **除小红书外的适配器全都没有 `diagnose()`** —— `_probe_login` 只认
   诊断结果里的 `login` 字段，抖音/视频号/头条号/公众号的适配脚本返回里
   根本没有这个字段 → 登录了也永远写不回 `logged_in`（小红书一直正常，
   正是因为只有它写了 diagnose）。四个适配器现已补齐 `diagnose`，
   统一报 `login / title / editor / fileInput` 等字段。
2. **登录发生在探测窗口之后就没有任何重探时机** —— 以前只在「打开发布页
   后 4~8 秒」探两轮。现在 `browser` 层给每个页面的 `loadFinished` 挂了
   防抖钩子（1.2s，登录必然伴随页面跳转），静下来后喊工作台
   `_on_login_hint` → `_probe_login` 重探并写回 → 账号矩阵灰点自动变绿。

目标账号弹窗顺带修复：以前只列「有待发布内容的平台」的账号，已勾选但
还没生成内容的账号在弹窗里**凭空消失**（看不见也取消不了）。现在弹窗
平台列表 = 有内容的平台 ∪ 已勾选账号的平台；无内容平台的组头标注
「暂无待发布内容」，账号可以先勾着备好。

配套测试：`tests/test_media_bar.py` 扩到 **130 条**（五个适配器 diagnose
/login 字段齐全、loadFinished 防抖钩子触发/失败不触发/异常吞掉、has_page、
弹窗平台合并与 content_keys 标注、工作台注册钩子的源码约束）。

### v1.6·5 追加：勾了没内容的账号，一键填充不再静默跳过

真机反馈：「选了两个账号，小红书和抖音，点一键填充会跳转到小红书，
对抖音不起效」。根因是**双重静默跳过**：

1. `_checked_accounts` 只遍历「有待发布内容的平台」——批次里没有抖音
   条目（内容条目按 Skill 平台拆分）时，勾选的抖音账号在这里就被丢掉；
2. `_dispatch` 的 `find_item(None) → continue` 再兜一层。全程一声不吭，
   用户自然认为「点了没反应」。

修复：

- **弹窗先问，不越权**：一键填充/发布前，对没有专属内容的勾选账号弹
  确认——「把本次内容也发过去」（多平台分发）或「跳过这些账号」。
- **跨平台复用**：各适配器按统一的 title/body/topics 字段取值，
  同批次内容天然可跨平台复用（`_item_for`：专属条目优先，复用时退回
  批次第一条；字数按各平台规则截断）。复用条目**不回写** artifacts，
  避免污染源平台的文件列表。
- **切页不错位**：`_on_step` 以前按「勾选列表」的索引把浏览器切到正在
  填充的账号——勾选数 ≥ 任务数时会切错页。现在用 `_dispatch` 实际构建
  的任务列表（`_dispatched_items`）。
- 被跳过的账号明确 toast 提示，不再无声无息。

配套测试：`tests/test_media_bar.py` 扩到 **143 条**（勾选列表补全、
`_item_for` 复用行为级测试（专属优先 / 未允许复用 → None / 复用 →
批次第一条 / 空批次退化）、确认弹窗与跳过提示、任务顺序切页的源码约束）。

### 一键填充填不上怎么办

浏览器工具条上有个 👁 **诊断当前页**。点它会把这个页面上「到底有什么」列出来：

```
是否登录：未登录（页面出现了登录框）
标题输入框：没有
正文编辑器：没有
配图上传控件：有
「上传图文」入口：有
发布按钮（xhs-publish-btn）：0 个
页面上 contenteditable：0 个 / input：12 个
```

对照着看就知道卡在哪一步。常见原因：

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 停在视频页（URL 无 `target=image`） | 旧版发布页地址 | 点「打开发布页」重开一次（现在会直接进图文页） |
| 有「上传图文」入口但没有编辑器 | 图文页要先有图才渲染表单 | 已自动处理：脚本会点上传控件，没配图时交给人工选图 |
| 提示「已帮你点开上传…再点一次」 | 内容里没配图，需要你手动选 | 选好图片，编辑框出现后再点一次「一键填充」 |
| 未登录 | 登录态过期 | 在该账号的浏览器里扫码登录 |
| 连标题框都没有 | 页面结构变了 | 改 `assets/adapters/xhs.js` 的选择器，不用重新打包 |

### 想换平台网址？想加新平台？

**改内置平台的网址**：`src/assets/platforms.json`，每个平台三个 URL：

| 字段 | 用途 |
|---|---|
| `login_url` | 登录页（账号矩阵里没账号时点平台名会引导到这里） |
| `home_url` | 后台首页（右键账号 → 「打开后台首页」） |
| `publish_url` | 发布页（点平台名 / 点账号行 / 「打开发布页」都走这个） |

改完重启程序生效，**不需要改代码、不需要重新打包**。

**加一个内置列表里没有的平台**（知乎、B站、百家号……）：
程序里直接加，不用碰文件 —— 「添加账号 → 平台 → ＋ 新增平台…」，
填名称、简称、主题色和网址即可。也可以点平台下拉右边的 ⚙ 改网址 / 删除。

自定义平台存在 `%APPDATA%\DragonFlow\platforms_user.json`，
与内置平台合并后使用（内置的排在前面，自定义的按创建顺序排在后面）。

> ⚠️ 自定义平台**没有自动填充脚本**（`assets/adapters/*.js` 只覆盖内置 5 个）。
> 发布时会自动降级为「复制内容到剪贴板 + 打开发布页」，由你手动粘贴 —— 不会卡死。
> 想让它也能自动填，需要照着 `四、平台适配脚本` 那一节补一个 JS 文件。

## 四·五、Skill 模板与上传格式

模板决定「AI 按什么套路写这个平台的内容」。每个平台可以配多个模板，
统一在「设置 → 内容模板 Skill」里管理；**工坊只列 `bundle`（Skill 包）+
`pipeline`（流水线）两种形态**（见「二·六」）。

模板有三种**形态**（`kind` 字段），决定点「生成内容」之后会发生什么：

| 形态 | 干什么 | 来源 | 进工坊吗 |
|---|---|---|---|
| `prompt`（模板） | 一次模型调用 → 输出结构化字段 | 默认。内置 6 个、上传的 json/md 都是这个 | ❌ |
| `pipeline`（流水线） | 多步骤：抓网页 / 出图 / 渲染视频 | 内置 3 条（见「四·六」），或自己写 `src/pipelines/xxx.py` | ✅ |
| `bundle`（Skill 包） | 整目录导入的 `SKILL.md`，作为方法论注入到 prompt 形态里；front matter 写 `kind: pipeline` + `pipeline: 运行器key` 则直接登记成流水线（见「四·六」末尾） | 上传一个含 `SKILL.md` 的文件夹 / zip | ✅ |

工坊里跑不起来的模板（prompt 为空）会**照样列出来**，但标「（不可用）」、
下拉项点不动，tooltip 里写清第一条 `err` 原因 —— 藏掉用户会以为「我明明传了怎么没有」。

### 上传（三种方式：选文件 / 选文件夹 / 导入压缩包）

`设置 → 内容模板 Skill → 上传 Skill ▾`，点开是个菜单：

| 菜单项 | 行为 |
|---|---|
| **选择模板文件…** | 多选 `.json` / `.md` / `.markdown` / `.txt` / `.zip` |
| **选择 Skill 文件夹…** | 选整个目录（递归）。目录里有 `SKILL.md` → 按 **Skill 包**整包搬进 `data/skills/<名>/`（附件一并保留）；没有 → 递归导入里面所有模板文件 |
| **导入压缩包…** | 多选 `.zip`。解包后按文件夹规则处理，**会拒绝绝对路径与 `..` 穿越条目** |
| **打开 Skill 目录** | 打开 `%APPDATA%\DragonFlow\skills` |

> 之前只能选文件，是因为上传按钮直接调了 `QFileDialog.getOpenFileNames()` ——
> 文件对话框天然选不了目录和压缩包。现在拆成三个入口，各用对应的对话框。

认这四种**文件内容**形态：

**1. DragonFlow 导出包**（点「导出」按钮得到的就是这个）

```json
{ "version": 1, "skills": [ { "name": "...", "platform": "xhs", "prompt": "..." } ] }
```

**2. 裸数组**

```json
[ { "name": "...", "platform": "xhs", "prompt": "..." } ]
```

**3. 单个模板对象**

```json
{
  "name": "小红书爆款笔记",
  "platform": "xhs",
  "content_type": "图文",
  "desc": "标题公式 + 短句排版 + emoji 小标题",
  "fields": ["title", "body", "topics"],
  "system": "你是深耕教育行业的小红书内容编辑……",
  "prompt": "围绕选题「{topic}」写一篇小红书图文笔记。\n【账号人设】{persona}"
}
```

**4. Markdown / 纯文本**（最省事，直接从别处复制一段提示词）

```markdown
---
name: 小红书爆款笔记
platform: 小红书
fields: title,body,topics
---

围绕选题「{topic}」写一篇小红书图文笔记。
【账号人设】{persona}
```

`---` 之间是头部（可只写 `name`），后面的正文整段作为 `prompt`。

### 字段说明

| 字段 | 说明 |
|---|---|
| `name` | 模板名（必填） |
| `platform` | 所属平台，中英文都认：`小红书`/`xhs`、`抖音`/`douyin`、`视频号`/`sph`、`公众号`/`gzh`、`头条号`/`toutiao` |
| `content_type` | 内容形态，如 `图文` / `短视频` / `公众号长图文`。**内容工坊的能力下拉直接读这个字段** —— 填一个新值（比如「播客」），下拉里就会出现「播客」这个能力，不用改代码 |
| `desc` | 一句话说明，显示在列表里 |
| `fields` | 要 AI 输出的字段，逗号分隔。可选：`title` `body` `topics` `cover` `image_hint` `hook` `cta` `digest` |
| `system` | 角色与红线（写进 system 消息） |
| `prompt` | 核心提示词，用 `{topic}` `{persona}` `{audience}` `{hook}` `{tone}` `{case}` `{cta}` `{extra}` 做占位符 |

### 内置模板怎么处理

> **v1.7 精简说明**：早期版本内置 6 个 prompt 模板（五个平台各一个 + 朋友圈短文案），
> 实测都只是单次模型调用、不能真的出图 / 渲染，已从内置库**整体移除**——
> 「只给选题也能生成」这条路现在由流水线 `multi_platform`（见四·六第 4 条）承担。
> 需要 prompt 模板的话在「设置 → 内容模板 Skill」里自己加即可，
> 停用 / 删除 / 编辑的行为不变（改动只存本机用户目录，不覆盖内置文件）。

内置的 4 条流水线模板（公众号转小红书图文（L）· 杂志风 / 文案转竖屏短视频 /
公众号链接转图文 + 短视频 / 一题多发选题转多平台内容）**留在工坊里** ——
它们由代码实现，是真会抓取 / 出图 / 渲染的那批。
删掉模板条目只是把入口藏起来，运行器还在 `src/pipelines/` 里。

用户上传的模板存在 `%APPDATA%\DragonFlow\skills_user.json`，
Skill 包存在 `%APPDATA%\DragonFlow\skills\<名>\`，
内置文件 `src/assets/skills.json` 永远不动。

### 可用性自检（保证装上的 Skill 都能用）

「装上了、界面上也选得到，一点生成却报错」是最糟的体验。所以每个模板
导入后都会立刻跑一遍 `SK.check_skill()`，分三档：

| 档位 | 含义 | 例子 |
|---|---|---|
| `err` **不可用** | 点生成必然失败，必须修 | 标了 `kind: pipeline` 但 `src/pipelines/` 下没有同名运行器；`prompt` 是空的 |
| `warn` **要注意** | 能跑，但产出可能不如预期 | 生成指令不足 30 字；描述了「抓取 / 出图 / 渲染」这类动作，但形态只是 `prompt` —— 那些动作**不会真的发生** |
| `info` 提示 | 不用改 | 指令里没有 `{topic}` 占位符，选题传不进去；`bundle` 形态的附件不会被执行 |

三个地方能看到结果：

1. **导入时** —— 上传完立刻弹提示：「「xxx」不可用：…」「「xxx」要注意：…」
2. **设置页列表** —— 每行右侧有 `不可用 N` / `注意 N` 标签，悬停看具体问题
3. **设置页「自检」按钮** —— 一键扫全部模板（含停用的），逐条列出

工坊也认这套判断：跑不起来的 Skill 包**照样列在下拉里**，标「（不可用）」+ 点不动 +
tooltip 里写第一条 `err` 原因；点生成时把它**摘掉并说明原因**，
其余能力照常生成 —— 不会因为一个坏包整批失败。

## 四·六、内容流水线（pipeline）

「模板」是**一次模型调用**；「流水线」是**多步骤流程**，中间有真实的代码执行和文件产出。
目前内置四条：

### 1. 公众号链接转小红书图文（`gzh_to_xhs`）

```
公众号链接 ──抓取──▶ 原文（标题/正文/配图）
                     │
                     ├─（可选）视觉模型逐张读配图 ──▶ 表格/数据抄成文字，并入正文
                     │
                     ├─ 模型读原文 ──▶ 8 页大纲 + 小红书文案（JSON）
                     │
                     └─ PIL 逐页出图 ──▶ 8 张 1080×1440 PNG
```

- 出图工具箱 `kit_draw.py` 提供 7 种版式：封面 / 列表 / 表格 / 要点 / 金句 / 段落 / 收尾。
  模型只负责「每页放什么内容」，版式由代码保证，所以不会出歪。
- 实测耗时 **40-90 秒**；勾上「读原文配图」再多 **20-40 秒**（并发读图）。

**抓不到正文时**，报错会告诉你具体是哪种情况，而不是笼统一句「抓取失败」：

| 页面特征 | 提示 |
|---|---|
| 微信返回「参数错误」 | 链接无效/被截断 → 回文章页「…」→「复制链接」重取 |
| 「环境异常」/「去验证」 | 请求太频繁 → 等几分钟，或用「手动粘贴正文」 |
| 「该内容已被发布者删除」等 | 文章已下架，说明原因 |
| 找到容器但正文 < 80 字且有配图 | 内容全在图里，纯文字抓不到 → 勾上「读原文配图」，用视觉模型抄出来 |

**配图里只有像素、没有文字** —— 这是中公类文章最要命的地方：招录规则、竞争比、岗位表
经常整张做成图。流水线对此有两层处理：

1. **自动警告**：正文 < 300 字且配图 ≥ 2 张时，日志会提示「产出可能偏薄」。
2. **「读原文配图」开关（默认开）**：用视觉模型逐张读配图，把图里的表格、竞争比、岗位表
   **原样抄成文字**，拼进正文再交给模型写文案。长图会先按 2.4:1 竖切成多块再送，避免整张
   缩到看不清。

⚠️ **前提是当前模型能读图。** 读不了图的模型**不会报错** —— 它会把图片静默丢掉，然后
一本正经地回答「无法识别图片内容」。所以这里必须提前判断：

| 服务商 | 能读图的模型 | 不能读图 |
|---|---|---|
| deepseek | `deepseek-flash` | `deepseek-v4-pro` |
| 智谱 | `glm-4v-plus` | `glm-4-plus` / `-air` / `-flash` |
| 通义 | `qwen-vl-max` | `qwen-plus` / `-max` / `-turbo` |

模型不支持读图时，流水线会在日志里明确说明，不会让你以为读过了。实测 `deepseek-flash`
读 7 张真实公众号配图 **24.7 秒**，抄出 2200 余字，`4990:1`、`67.17分` 这类只在像素里的
数字全部抄对。

### 2. 文案转竖屏短视频（`xhs_video`）

```
文案 ──模型──▶ 分镜脚本（封面/要点/数字/段落/收尾 + 每镜口播）
                │
                ├─ edge-tts 逐镜合成语音 ──▶ 用真实语音时长决定每镜停留时间
                │                            （可选）垫一层无版权和声
                │
                └─ PIL 逐帧渲染 RGB 裸帧 ──管道──▶ ffmpeg ──▶ H.264 + AAC mp4
```

- 口播用 **edge-tts**（免费、需联网），4 种中文音色可选；选「不要口播」则走固定节奏。
- ffmpeg 用 **imageio-ffmpeg** 自带的二进制，用户不需要单独装 ffmpeg。
- 画面是元素错峰入场 + 打字机效果；背景是深蓝渐变 + 柔光斑，逐镜微调。
- 实测耗时约为成片时长的 **4 倍**（21 秒的片子约 90 秒）。
- 渲染在后台线程跑，弹窗里可以点「停止」中断。

### 3. 公众号链接 → 图文 + 短视频（`gzh_to_both`，组合流水线）

把上面两条串起来：**贴一条链接，同时拿到小红书图文和竖屏短视频。**

```
公众号链接 ──▶ gzh_to_xhs ──▶ 文案 + 8 张配图
                    │
                    └─ 拿上一步产出的「标题 + 正文」──▶ xhs_video ──▶ 9:16 mp4
```

关键点：**中间的文案由前一步产生，不让你填第二遍**。
`gzh_to_both.inputs()` 把两条流水线的输入合并去重（`title` / `body` 这类
「上一步产生、下一步消费」的字段直接**不进输入表单**），
所以表单里只会出现：链接、手动粘贴正文、读原文配图、出图页数、分镜数量、口播音色、背景音乐、补充要求。

> 这条流水线的代码在 `src/pipelines/gzh_to_both.py`，思路是「能力可以互相调用」——
> 想再串「链接 → 图文 + 视频 + 公众号长图文」，照着它加一步即可。

### 4. 一题多发 · 选题转多平台内容（`multi_platform`）

内容工坊第一条「从选题开始」的流水线：**不要求手上先有现成文章**，只给一个选题，
一次拿到多平台的全套内容。

```
选题 ──搜狗检索（备用 360）──▶ 事实底料（标题 + 摘要）
        │ 全部失败自动降级为模型常识，日志里会提示人工核对
        │
        └─ 一次模型调用 ──▶ 结构化 JSON（四块）
             ├─ 小红书图文：标题/正文/话题/封面 + N 页大纲 ──▶ kit_draw 出图
             ├─ 公众号长文 ──▶ md + docx 落盘
             ├─ 知乎/头条观点文 ──▶ md + docx 落盘
             └─ 短视频口播稿 ──▶ 复用 xhs_video 全套渲染 ──▶ 9:16 mp4
```

- 「产出范围」可选 **全部 / 仅图文 / 仅文章 / 仅视频**，只想改一种时选单项能省一大半时间。
- **事实纪律**写死在提示词里：硬事实（数字/日期/政策）只能来自检索底料，
  易变信息必须带时间限定，各平台之间事实一致、角度差异化。
- 小红书图文走 `gzh_to_xhs_magazine` 的**奶油杂志风版式**（MagazineDeck 暖橙奶油色系），
  视频与 `xhs_video` 同一套渲染管线且**固定走 cream 主题**（暖橙奶油底 + 深棕文字），
  与图文同一套视觉；文章用 python-docx 落盘（微软雅黑 + 主题色标题）。
  深蓝版式（navy）只保留在 `gzh_to_xhs` / `xhs_video` 单独运行时的默认主题里，
  一题多发内部不引用。
- **为什么检索用搜狗**：实测必应对免登录的程序化请求会把结果降级成查询首词的通用内容
  （「广东选调生 机考」只回「广东省百科」），百度直接出验证页；搜狗免登录结果相关度最高。
- 实测耗时约 **3-6 分钟**（全部产出）；视频渲染约为成片时长的 4 倍，占大头。
- 生成等待有可视化：底部动作条显示**进度条 + 已用/约剩时间**，结果卡胶囊显示百分比；
  各阶段进度做了区间标定（检索→模型→出图→文章→视频只进不退）。

### 自己加一条流水线

```python
# src/pipelines/my_flow.py
from .base import Ctx, Input, Pipeline, register

@register
class MyFlow(Pipeline):
    key = "my_flow"            # 要和 assets/skills.json 里的 pipeline 字段对上
    name = "我的流水线"
    desc = "一句话说明"
    platform = "xhs"
    fields = ["title", "body"]

    def inputs(self):
        return [Input("topic", "选题", "text", placeholder="例如：省考行测怎么提速")]

    def run(self, values, ctx: Ctx):
        ctx.progress(0.1, "调模型")
        text = ctx.llm("你是内容编辑", f"围绕 {values['topic']} 写一段话")
        path = ...                       # 自己出图 / 出视频
        ctx.add(path)                    # 登记产物，弹窗里会显示缩略图
        ctx.check()                      # 检查是否被取消
        return {"title": values["topic"], "body": text, "_artifacts": [path]}
```

再在 `src/pipelines/__init__.py` 里 import 它，然后到 `assets/skills.json`
加一条 `{"kind": "pipeline", "pipeline": "my_flow", ...}` 即可。

`Ctx` 提供：`log()` / `progress()` / `check()`（取消检查）/ `add()`（登记产物）/
`llm()` / `llm_json()` / `out_dir`。

### 让上传的 Skill 包直接绑定流水线

描述了「抓取 / 出图 / 渲染」的 Skill 包（比如仓库 `skill/` 下的 gzh-to-xhs），
以 bundle 形态导入只会做一次文本生成 —— 自检会给 warn：那些动作不会真的发生。
正解是给它配运行器，并在包的 `SKILL.md` front matter 里声明绑定：

```yaml
---
name: gzh-to-xhs
kind: pipeline
pipeline: gzh_to_xhs_magazine
---
```

导入时 `_import_pack` 读到这两个字段，就把包登记成**流水线形态**：
工坊里显示运行器声明的输入表单（链接 / 读配图 / 页数…），
点生成真的会抓网页、读配图、出图、写文件。没声明这两个字段的包维持 bundle 行为不变。

现成的例子：`gzh_to_xhs_magazine`（`src/pipelines/gzh_to_xhs_magazine.py`）——
抓取 / 读配图 / 大纲完全复用 `gzh_to_xhs`，出图换成该 skill 自带设计规范的
**暖橙奶油杂志风**（奶油底 + 深棕墨 + 暖橙高光词 + 杂志刊头封面 + 暖棕投影）。
换肤只覆写了 `Deck` 的封面 / 表格行底 / 金句 / 收尾几处，其余版式继承自 `kit_draw`。

## 四·八、目标账号与差异化分配

一个平台挂 5 个账号、只生成 1 条内容，5 个账号发一模一样的东西容易被判重复。
工作台工具栏的「目标账号」弹窗解决这个（点它右下角的「差异化分配…」进入网格）：

- **网格勾选**：哪条内容发给哪些账号，一眼看完（默认全勾，**未登录的账号不默认勾**）
- **差异化**：给某个账号勾上，点「为勾选账号生成差异化版本」，
  模型会在**不改事实与数字**的前提下换标题、换开头两段、重排话题标签
- 差异化版本存在 `DraftItem.variants[account_id]`，填充时按账号取用
  （`it.content_for(account_id)`），没有版本的账号自动回退原文

> 差异化会为每个账号各调一次模型，账号多时耗时较长，弹窗里有进度条。

  工坊里，3 条内置流水线在；工坊能力清单 == `skills.studio_skills()`；
  有流水线时列表是显示的、不是引导面板（引导面板那条分支靠打桩把清单变空来验）
- **工坊拦住跑不起来的能力** —— 塞一个 prompt 为空的假 bundle，下拉里要出现、
  标「（不可用）」、model 里被 `setEnabled(False)`、强行加会被拒
- **多个能力共用输入只出现一次** —— 勾 2 条 Skill 包，`topic` 这个 key 只出现一次，
  提示里写明「会同时喂给 2 个能力」
- **填写输入弹窗** —— 输入不再内嵌在页面上；弹窗里共用的输入只渲染一次、
  开关 / 下拉按默认值预置、重开弹窗带回上次填的值；摘要会随填没填改口，
  缺必填时点「开始生成」直接把弹窗顶出来
- **导航不覆盖批次** —— 从素材库点「复用到工作台」，草稿不会被空批次冲掉

> 判「面板有没有被隐藏」要用 `isHidden()`，不要用 `isVisible()` ——
> 用例里工坊不是当前页，父级没显示，`isVisible()` 会恒为 `False`，断不出东西。

**用临时数据目录跑** —— 在 `import config` **之前**把 `APPDATA` 指向
`tempfile.mkdtemp()`，于是 `config.DATA_DIR`、素材库、`skills_user.json`、
账号文件全部落在临时目录里。**不碰你本机的任何数据**，跑完直接
`shutil.rmtree(tmp)` 删掉，不用还原、也没东西可还原。

```python
_TEST_DATA = tempfile.mkdtemp(prefix="dragonflow_reuse_")
os.environ["APPDATA"] = _TEST_DATA          # 必须在 import config 之前
...
assert config.DATA_DIR.startswith(_TEST_DATA)   # 自检：确实隔离了
```

> 早先这里是「备份 → 跑 → 还原」（`finally` 里把备份整个文件覆盖回去）。
> 那个方案有个**棘轮效应**：只要一次跑到一半被杀（Ctrl-C / 超时 / 沙箱 SIGTERM），
> `finally` 不执行，fixture 就留在真实库里；**下次跑时备份的已是被污染的那一份，
> 还原出来还是脏的**。症状是「内置模板自检突然多出几个不认识的包」
> （实际报过一次 `['拆解重组包', '钩子开头包', '口播分镜包']`），
> 极难反查到是测试留下的 —— 所以改成整体隔离，从根上断掉。

> ⚠️ 在**带「删除守卫」的沙箱环境**里（比如 AI 助手自己的沙箱），
> 同一轮里连续跑多套测试会把守卫的滑动窗口打满，之后**所有「写 JSON」
> 都会失败** —— 常见的原子写是 `写 .tmp` + `os.replace(tmp, path)`，
> 而 `os.replace` 会删掉源文件，正好踩在守卫上。
> 症状是「单跑绿、连跑红，红的总是排在后面那套」。
> **普通环境 / CI 不会有这个问题**，遇到时单独再跑一次、或给用例之间加个间隔即可。

## 六、几个必须知道的坑

改这个项目前请先读这一节，都是踩过的。

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **WebEngine 导入顺序** | 进程直接消失，无任何报错、无 traceback、退出码 0 | `PyQt6.QtWebEngineWidgets` 必须在 `QApplication` **之前**导入 |
| **QFontDatabase 调用时机** | 同上：进程静默消失，退出码 127，日志只打印到调用前一行 | `theme.init_font()` 必须在 `QApplication` **之后**调用（已加断言，会抛明确异常而不是静默崩） |
| **QWidget 不画背景** | `#Card` 白底、输入框、导航栏全都"隐形" | 自定义/裸 `QWidget` 必须 `setAttribute(WA_StyledBackground, True)`；已封装为 `theme.apply_styled_bg(win)`，启动时统一扫一遍 |
| **deleteLater 是延迟的** | 清空列表后旧控件还在原位，出现"两个空状态叠在一起" | 清布局必须 `takeAt` + `setParent(None)` + `deleteLater`；统一用 `theme.clear_layout(lay)` |
| **.bat 必须 CRLF 行尾** | cmd 把行拆错、拼出垃圾命令，报 `'py' 不是内部或外部命令` 之类莫名错误 | .bat 一律 **CRLF + GBK**（中文 Windows 控制台原生码页 936，因此不需要 `chcp`）；改完用 `od -c` 确认没有裸 `\n` |
| **离屏环境无字体** | 中文全是方块 □□□ | `theme.init_font()` 会退回按路径加载 `C:\Windows\Fonts\msyh.ttc`，这也是交付到别人机器上的兜底 |
| **输入框隐形** | `BG_INPUT` 与 `BG_PAGE` 同色 | 输入控件一律带常显描边 `BG_INPUT_LINE`，不依赖底色对比 |
| **表单横向拉满** | 设置/工坊页内容铺满 1400px，稀疏不专业 | 用 `theme.PageScroll(max_width=...)` 限宽居中 |
| **裸样式表污染子孙**（最坑） | 主按钮变成「白底 + 蓝边 + 白字」，完全看不见 | 绝不写 `w.setStyleSheet("background:xxx;")` 这种**没有选择器**的裸声明 —— Qt 会把它作用到该控件**及其全部后代**，冲掉子控件自己的背景。统一用 `theme.paint_bg(w, color)`（内部用 objectName 限定选择器） |
| **minimumWidth 顶住收起动画** | 侧栏 `maximumWidth` 已经归 0 了，实际宽度纹丝不动，看起来「点了没反应」 | 做宽度动画必须 min / max **一起动**（`QParallelAnimationGroup`），或先 `setMinimumWidth(0)` |
| **QScrollArea 的 sizeHint 不老实** | 弹窗明明屏幕放得下，却永远按最小可滚动尺寸弹出，或者内容压成重叠 | 别信 `sizeHint`，按 `head + body + foot` 显式求和；超屏才交给滚动区 |
| **QDialog 高度不够时内容重叠** | 提示文字直接压在输入框上，像渲染花了 | 弹窗内容一律用 `QScrollArea` 承载，`showEvent` 里做一次自适应尺寸 |
| **`QScrollArea.setWidget()` 会删掉旧控件** | 弹窗关掉后卡片全没了 / 程序崩溃 | 要把控件「搬走」用 `takeWidget()`（只解父子关系，不销毁）；`setWidget()` 会 `delete` 掉原来的 |
| **动态属性变了 QSS 不生效** | 设了 `setProperty("checked", True)` 但样式没变 | 改完属性必须 `style().unpolish(w)` + `style().polish(w)`；属性值用 Python `bool`，QSS 里写 `[checked="true"]` |
| **列表控件加 stretch 后新项跑到下面** | 新加的卡片出现在「撑开的空白」之后 | `addStretch(1)` 之后要用 `insertWidget(count()-1, w)`，不能 `addWidget` |
| **PIL 在 RGB 图上画半透明色** | 想画一层 10% 白的卡片，结果要么纯白糊住、要么完全看不见 | alpha 在 RGB 图上会被忽略。半透明元素要画在独立的 `RGBA` 图层上，最后 `Image.alpha_composite(bg.convert("RGBA"), ov)` 合回去（见 `xhs_video._compose`） |
| **ffmpeg 不会自己建目录** | `Error opening output ...: No such file or directory` | 编码前先 `os.makedirs(os.path.dirname(out), exist_ok=True)`；`Pipeline.output_dir()` 已经做了，但自己拼路径时容易漏 |
| **PIL 管道喂 ffmpeg 要 flush 干净** | 视频最后几帧丢失 / 进程卡住不退出 | 写完 `proc.stdin.close()` 再 `proc.wait()`；`-shortest` 只在有音轨时加 |
| **GUI 调 ffmpeg 闪黑框** | 每次合成视频/读音频都闪一个控制台黑框（标题是 `_MEI…\imageio_ffmpeg\binaries\ffmpeg-….exe`） | GUI 进程调控制台子程序必须带 `creationflags=subprocess.CREATE_NO_WINDOW`（仅 Windows 有此属性，用 `os.name=="nt"` 守卫，见 `xhs_video._NO_WINDOW`） |
| **`.zip` 解包必须防穿越** | 压缩包里 `../../x.txt` 或 `/etc/x` 会写到目录外 | 逐条校验：绝对路径、`..` 段一律跳过。别直接用 `extractall()` 图省事 |
| **流水线跑到一半关弹窗** | 线程还在渲染，程序退不掉 / 半截文件 | `closeEvent` 里 `cancel()` + `wait(4000)`；pipeline 内部每步 `ctx.check()` 抛 `InterruptedError` |
| **口播时长决定画面时长** | 画面固定 3 秒但语音 6 秒，音画对不上 | 逐镜合成语音 → 用 ffmpeg 读真实时长 → 用它决定该镜帧数，而不是拍脑袋定时长 |
| **模型要填接口 ID，不是显示名** | `400 invalid_request_error: The supported API model names are ...` | 官网写 `DeepSeek-V4.1-Flash`，接口认 `deepseek-flash`。用「拉取可用模型」按钮直接问服务端，别手抄 |
| **推理模型的思考吃输出额度** | 调用成功但正文 0 字，或 JSON 被截断成半截 | 思考 token 和正文共用 `max_tokens`。`llm.effective_max_tokens()` 给推理模型兜了 6000 的下限，`finish_reason == "length"` 时自动翻倍重试 |
| **长 QLabel 不换行会把整页撑宽** | 行尾的按钮「不见了」——不是被压扁，是跑到屏幕外，且横向滚动条默认关着滚不过去 | 提示类/描述类 `QLabel` 一律 `setWordWrap(True)`；`theme.PageScroll` 也加了兜底：内容最小宽度超过视口时自动打开横向滚动条 |
| **HTMLParser 对自闭合标签会 start+end 各调一次** | 用「标签深度」判断正文边界时，`<img />` 让深度被扣到 0，正文整段丢失且不报错（实测 5270 字的文章只抓到 568 字） | 别自己数深度：先用 `<div>`/`</div>` 配对把正文容器切出来，再整体当正文解析（见 `gzh_to_xhs._extract_content_html`） |
| **`QFileDialog.getOpenFileNames()` 选不了目录** | 用户想传文件夹/压缩包，但根本点不进去 | 「上传」这类入口要做成菜单：`getOpenFileNames`（文件）+ `getExistingDirectory`（文件夹）+ `.zip` 解包，三条路汇到同一个导入函数 |
| **`runJavaScript` 不 await Promise** | 脚本里 `await sleep(1200)` 后接着填，结果永远填不上 —— 页面其实还没渲染 | `Promise.resolve(x)` 回到 Python 侧是 `{}`。等待只能在 Python 侧做：脚本返回 `retry:true`，队列延迟重跑（见 `publisher.PublishQueue`，有 `test_js_promise.py` 守着） |
| **「图文 / 视频」是两个 URL，不是同页两个 tab** | 发布页默认落在视频页，那里压根没有正文编辑器 → 永远报「没有找到正文编辑器」 | 直接把发布页地址指到 `target=image`，别指望点 tab 切过去（`platforms.publish_url_for`） |
| **受控输入框的「隐藏替身」** | 标题怎么填都是空 —— 填进了一个 4px 宽的假框，Vue/React 不 commit | 取值必须带宽度过滤（`offsetWidth >= 50`）；一个都不够宽时退而取**最宽**的那个，仍躲得开替身 |
| **发布按钮在 closed shadow DOM 里** | 点了没反应，表单不提交（host 级 `.click()` 进不去内部 handler） | 直接调 web component 的实例方法（`_onPublish` / `onPublish` / `_onSubmit` / `_handleSubmit`），全 miss 再按可见文本点 `button` 兜底 |
| **结果条被「重建」冲掉** | toast 说「部分账号未完成」，底部 chip 却显示「待填充」，点进去也没原因 | 逐账号的执行结果要单独存（`workbench._last_result`），别在跑完时按「平台级」状态重建；失败原因挂到 chip 的 tooltip 上 |
| **字段解析：列表 vs 成句文本** | 配图永远传不上去。`image_hint` 的值是「已出图 8 张，目录：J:/…」这种**成句说明**，被按空格拆成 `['已出图','8','张','目录：J:/…']`，发布时解析不出目录 | `_from_text()` 只对 `topics` 按空格 / 逗号拆；`image_hint` / `shot_hint` 原样保留 |
| **主窗口导航回调的副作用** | 从素材库点「复用到工作台」，工作台和「待发布内容」里都看不到 —— 刚设好的草稿被一个空批次覆盖了 | `BUS.goto_workbench` 只负责**导航**。要不要同步内容，由发起方自己决定（工坊点「去发布」时自己 push，素材库复用时自己 set_batch） |
| **Skill「装上了却跑不动」** | 界面上选得到，一点生成就报「缺少运行器」，或者只得到一段缺了动作的文本 | 导入后立刻跑 `SK.check_skill()`：`err`（必然失败）/ `warn`（能跑但不对）/ `info`。设置页每行标 `不可用 N` / `注意 N`，另有「自检」按钮扫全库 |
| **「平台要求先传素材」≠「这次有文件可传」** | 内容里没配图时，适配脚本一步都不点上传 → 永远停在「没有找到正文编辑器」（小红书图文页就是先传图才渲染表单） | 两件事拆开：`_want_upload`（平台要求，每次尝试都带）/ `_upload_count`（文件数，仅首次）。没图可传时主动点开上传并返回 `manual: true`，交给人工选图 |
| **`manual: true` 不是失败** | 把「需人工介入」当失败报，用户以为程序坏了 | 结果条按 `meta.manual` 显示**「需人工」**（暖色），不是红色「失败」；消息里写清下一步该干什么 |
| **「打开过发布页」≠「已登录」** | 账号矩阵里没登录的账号也显示「正常」、还被默认勾选进发布目标 | 不能臆断写 `logged_in: True`。打开页面后延迟探测真实登录态（`PUB.diagnose` 读 `login` 字段），未登录显示灰点 + 「未登录」标签、不默认勾选 |
| **`QParallelAnimationGroup` 没有 `valueChanged`** | 想在手柄跟随动画时重算位置，连信号直接 `AttributeError` | 把 `valueChanged` 挂到**子** `QPropertyAnimation` 上，不是在 group 上（group 只聚合，不转发该信号） |
| **Windows 任务栏图标不跟着变** | `setWindowIcon` 设了，任务栏还是 python.exe 的默认图标 | 任务栏按 AppUserModelID 归组。必须 `SetCurrentProcessExplicitAppUserModelID("DragonFlow.OneLine")`（要在 `QApplication` 之前），打包 EXE 再加 `icon=` |
| **「矩阵分配」和「目标账号」是同一件事** | 工具栏两个按钮都在选「发到哪些账号」，用户不知道该点哪个 | 保留「目标账号」，把「矩阵分配」收进它的弹窗（「差异化分配…」）。入口少了，功能没少 |
| **QSS 的 `indicator:checked` 只写 background → 没有对勾** | 想给勾选框做「选中变蓝」，结果只是一块纯蓝方块，看不到打勾（用户原话：「不要蓝白色块」） | 对勾得自己给：`theme.check_tick_path()` 用 QPainter 画一张白对勾 PNG 存到数据目录，QSS 里 `image: url("…")`。**QSS 的 image 只认文件，不认 QPainter**；而且必须在 `QApplication` 之后渲染（QPixmap 依赖它） |
| **「选择」的选中态别只靠颜色块** | 整张卡片变淡蓝底，用户看不出「到底勾没勾」，一屏里好几块蓝色 | 选中态**只**由勾选框表达；整行最多给个 hover 底色。颜色留给状态（成功/失败/需人工），不要跟「选中」抢 |
| **`QComboBox` 不画箭头 = 长得像输入框** | 设置页的「服务商 / 模型」两个框看着像文本框，用户不知道能点开选 | QSS 里 `QComboBox::down-arrow` 必须自己给 `image:`。用 `theme.icon_png("chevron_down", …)` 把矢量图标渲染成 PNG 再拼进去（**QSS 的 `image:` 只认文件，不认 QIcon**）。`::down-arrow:on` 那条规则渲染失败时**整条都别写** —— 写个空的 `url("")` 会把上一条也盖掉，箭头反而彻底没了 |
| **用「✓」这类字符当标记会变豆腐块** | 下拉里给已选项加个 `✓` 前缀，在字体不全的环境里渲染成一个「口」 | 勾选标记用 **item icon**（`combo.setItemIcon`），别用字符。同理，任何「靠某个具体码位」的装饰都要先怀疑字体覆盖 |
| **输入收进弹窗后，控件读不到值了** | 弹窗一关控件就销毁，再 `read_values()` 全是空 | 值的权威来源换成**缓存字典**（`studio._input_values`），弹窗保存时落进去。缓存里缺的 key 要补 `Input.default` —— 否则开关 / 下拉这些「本来就有默认值」的输入会被误报成没填 |
| **页面上把每条选项都铺开 = 一屏列表** | 十几条能力每条一张卡（名称 + 描述 + 要填/会得到 + 两个胶囊），页面被顶得很长 | 能收进下拉就收进下拉，长文本挪到 **tooltip**；已选项用胶囊列出、点 `×` 移除。判据是「用户要选的是哪一个」，不是「把每个选项介绍一遍」 |
| **窗口 `resize()` 比屏幕可用区还大** | 初始界面「藏到桌面任务栏下面」—— 底边整条被任务栏压住，最下面那排控件点不到 | 别硬写 `resize(1440, 940)`。跟 `screen().availableGeometry()`（**已扣任务栏**）取交集再居中；`setMinimumSize` 也要一起压，否则它会把窗口重新顶出屏幕。判据是 `availableGeometry().contains(win.geometry())`，别拿 `geometry()` 比（那里面含任务栏） |
| **浮层手柄「贴底 + 避让底部条」** | 手柄掉在角落像颗扣子；底部一有结果条就得往上让，让多少靠 `bottom_bar_height()` 估，布局一改就压住它 | 竖向居中（`(body.height() - hh) // 2`）—— 中点永远空着，不用管底部有什么。20px 宽骑在分界线上，只有 10px 探进侧栏，正好落在侧栏 12px 的右边距里 |
| **测试写真实数据：备份 + 还原是漏一个就污染** | 用例建了「知乎测试号」账号 + 自定义平台，只还原了 `platforms_user.json`；中途一挂就在 `accounts.json` 里留下孤儿账号，还会连带让 `test_adapters`（按平台找适配脚本）变红。更狠的是**棘轮效应**：被 SIGTERM 杀一次，fixture 就永久留在真实库里，之后每次「还原」还原的都是脏的那一份 | 别逐文件备份还原，**把整个数据目录隔离掉** —— 在 `import config` 之前把 `APPDATA` 指到 `tempfile.mkdtemp()`，`config.DATA_DIR` 连带素材库 / `skills_user.json` / 账号文件全落进临时目录，跑完 `rmtree`。写用例时加一句 `assert config.DATA_DIR.startswith(_TEST_DATA)` 自检 |

> **判断截图是否真的渲染了文字**：看 PNG 大小。豆腐块/空白约 15KB，
> 正常渲染中文约 60–170KB。这是个很好用的快速判据。


产物为单文件 EXE，绿色免安装。

> ⚠️ 不要加 `--clean`，会清掉 Qt 的缓存导致打包结果异常。

打包时 `build/dragonflow.spec` 会把 `imageio-ffmpeg` 自带的 ffmpeg 二进制一起塞进去
（约 88MB），所以最终 EXE 会比纯图文版本大一圈。没装这个包也能构建成功，
只是打包后视频功能不可用（源码运行不受影响）。
